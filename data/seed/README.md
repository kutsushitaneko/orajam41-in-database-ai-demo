# 教材のラックサーバーと保守ナレッジ

このデータセットは、企業が運用する架空の業務用ラックサーバーの保守問い合わせを題材にしています。ブラウザーから利用する管理画面があり、稼働状態の確認や保守ログの取得を行う想定です。

- AX-100、BX-200、CX-300：架空のラックサーバーの機種名。
- DEV001〜DEV012：メーカーがサーバー1台ごとに発行する保守登録番号。`OJ41_DEVICES.device_id`に対応します。
- `model`：機種名。同じ機種でも保守登録番号と契約は別です。
- `serial_no`：架空の製造番号。デモではこれによる検索を実装していません。

`knowledge.json`の管理画面、LAN、温度・電源警告、ディスク残量、ログ保存の記述は、この架空サーバーの手順です。実在製品の保守手順には使いません。データとコードに出てくる「機器」「device」は、このサーバーを指します。

対象の指定は、利用者がメーカーの保守ポータルや契約書で確認した保守登録番号を入力する前提です。PythonのRAG検索は保守登録番号を閲覧可能な台帳と照合して機種を取得し、Agentは対象の保守登録番号をセッションへ固定してツール側で検査します。症状だけから対象を推測する機能、ラベルの画像認識、保守登録番号を聞き返す対話は実装していません。

契約の期間・範囲やエラーコードの意味は教材用の定義です。保守登録番号・機種・期待する検索結果の関係は[共通データの説明](../../docs/demo-data.md)を参照してください。

メーカーの保守担当者が受付済み案件SR001を開き、受付表で顧客C001を確認します。その顧客の契約一覧で保守登録番号を照合します。SR002を開けばC002に対応します。DB接続は共通で、顧客ごとのDBユーザーは不要です。期限切れ契約も照会でき、技術手順の案内と現地保守の利用可否は分けます。
